# 72星 Cesium 渲染基线与下一步

2026-10-12（America/Vancouver）。在公开发布完成后，用无登录浏览器访问生产站点并做渲染对照；没有增加星座研究案例或改变物理模型。

## 已观察的结果

Chrome无头模式、SwiftShader软件渲染、390×844视口、72星50°候选、足印32顶点。每组动画约2.5秒；这是本机诊断数据，**不是手机真实FPS测量**。复现脚本为 `scripts/profile_coverage.cjs`，原始数据在 `examples/performance-baseline.json`。

| 显示方式 | 单次统计/足印更新均值 | 动画帧间隔均值 | 观测FPS |
|---|---:|---:|---:|
| 足印＋轨迹 | 7.65ms | 449.99ms | 2.22 |
| 关闭足印，保留轨迹 | 0.34ms | 113.76ms | 8.79 |
| 关闭足印和轨迹，只留点 | 0.31ms | 128.33ms | 7.79 |

关闭足印改善明显，单纯关闭轨迹未在这个短样本中继续改善。测量说明应优先处理足印绘制，不能据此推断所有设备都能提升相同倍数。统计更新耗时远小于完整帧间隔，主线程边界计算并非唯一瓶颈。

## 代码中的具体开销

当前足印每颗星用32（手机）/64（桌面）个方位点，每点32次二分求根。72星每次刷新约73728/147456次边界迭代，生成许多Cartesian3对象；约每180ms刷新一次。

每颗星的Polygon和Polyline都通过非恒定CallbackProperty返回动态几何，存在频繁几何处理和大量透明叠绘的开销。轨道位置已从采样星历插值，未在Cesium每帧重新做完整天体数值积分。因此本轮建议首先优化展示层。

参考：[Cesium CallbackProperty文档](https://cesium.com/learn/cesiumjs/ref-doc/CallbackProperty.html)、[Scene显式渲染选项](https://cesium.com/learn/cesiumjs/ref-doc/Scene.html)、[官方显式渲染性能说明](https://cesium.com/blog/2018/01/24/cesium-scene-rendering-performance/)。文档支持这些机制；具体收益须在固定场景与目标手机上验证。

## 建议的改造顺序（尚未实施）

1. **将覆盖统计与显示更新拆开。** 轨道位置平滑插值，足印显示按较低频率更新；统计和导出仍按指定步长计算。低频显示需标注时间和刷新间隔。
2. **用Worker生成并缓存WGS84边界。** 按仿真时间片缓存，在拖动时间轴时复用；控制内存上限。浏览器的网络时延计算已经在Worker中，现有足印边界仍在主线程。
3. **批量绘制足印。** 使用批量几何或覆盖纹理，减少逐星动态Entity、多边形重建及透明叠绘。若显示层使用近似或栅格，单独说明显示精度，保留精确站点计数。
4. **暂停时按需渲染、手机提供轻量显示。** 使用显式渲染机制减少暂停时的空转；按屏幕与相机距离选择足印顶点数，并保留完整模型的计算结果。

下一轮验收应同时比较：相同轨道/时刻下计数和RTT保持一致、真实手机帧率与内存、拖动时间轴响应、暂停时CPU占用。当前版本没有宣称72星已完成性能优化。
