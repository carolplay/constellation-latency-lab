两个工具，三种模型范围

1. 动态星座覆盖图

输入高度、倾角、轨道面数 P、每面星数 S、Walker 相位 F、RAAN 原点、初始相位、仰角、UTC 历元。可添加多个轨道层；圆轨道使用 Kepler＋长期 J2。Delta 在360°均布轨道面，Star 在180°范围按180°/P间隔排布，部分轨道面模式的跨度包含两端。

WGS84 足印按椭球法向仰角求解；半透明锥体为球面近似。均不考虑机械指向、光学误差、真实天线波束、天气、容量和遮挡地形。航线97点覆盖既不是连续走廊证明，也不是端到端网络连通证明。

“新建星座”中的新方案保存在你的本机浏览器。下载 JSON 可在时延工具复用；下载 CZML 可导入其他 Cesium Viewer。清除浏览器存储会移除本机方案。

2. 网络时延模拟

网页几何模式：星间距离上限、大气边界、地面仰角、传播与处理开销；所有可见星地链路即时可用。四邻居网格每层独立，部分/Star的面接缝保持开口；任意选边是假设无限终端的乐观模型。

Python 工程模式：在现有抽象模型中加入固定在 LVLH 的标称终端方向、FOV、相对机械转速、多普勒、捕获时间、地面天线槽位与 Make-Before-Break。默认参数是假设，不是厂商设备规格；仍无真实链路预算、天气、队列或因果包级传播。

RTT 是2×同一快照对称 OWTT。每个经过的卫星收一次处理开销，星地每条腿每方向计一次调制解调。在线 P99−P1 是时延跨度。中断为缺失时延；全天无服务比例超过1%时，无条件P99视为无穷。采样可用率100%不等于连续时间或永久服务证明。

配置与复现

两个工具共用 schema_version=1 的 JSON：name、shells、simulation、physics、topology。网页支持最多500星和20000个快照；任意选边最多150星。网页轨道为圆轨道；Python核心另外保留逐星六要素与离线TLE接口。

pip install -e .
constellation-cover --config configs/candidate72.json --out outputs/my-coverage
constellation-latency --config configs/candidate72.json --mode geometry --out outputs/my-network
constellation-latency --config configs/candidate72.json --mode engineering --out outputs/my-engineering

新增公共预设：添加 configs/*.json 与 data/catalog.json；如有预先计算的统计，在 data/preset-metrics.json 记录来源，再运行 scripts/build_site.py。未审核的新方案不要填写假定100%的覆盖统计。

预设出处

18/36/72星为本项目合成配置。Globalstar使用历史48星布局，虚拟激光结果是反事实；其实际网络使用地面转发。Lightspeed使用2020年298星双层申报重建，面间相位与初始对齐为假设；这些不是当前实时舰队TLE。

金融地面站坐标为机房附近估计；东京为城市代理。58.9/155/7.97ms地面基准为用户情景输入，不是本工具独立实测SLA。来源和研究结果见开源仓库中的 data/ 与 docs/。

本次发布整理现有研究与工具，没有继续扩大星座参数扫描。
